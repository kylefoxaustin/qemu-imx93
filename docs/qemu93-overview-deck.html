NXP i.MX 93 · Full-System Emulator

QEMU i.MX 93 — boot the real software stack,
no silicon required.

The first full functional model of the i.MX 93 SoC in QEMU. It boots U-Boot and a stock NXP BSP Linux on a virtual i.MX 93 — a heterogeneous 2× Cortex-A55 + Cortex-M33 machine. There is no System Manager to lean on: Linux programs the clocks and power (CCM / ANATOP) directly, exactly as it does on the silicon, and the model answers.

Honest limits

What doesn't work — and why

A short list — the i.MX 93 is a leaner SoC than its i.MX 95 sibling, so there is simply less to be missing. Every gap has one cause: a per-die secret we can't fake, or an upstream driver/QEMU model limit. Nothing is hand-waved.

No GPU · no VPU · no hardware JPEG
Not a model gap — the i.MX 93 silicon has none of these blocks. There is no 3D or video-codec engine to emulate; JPEG and video are software on this part. (Its 2D path is the PXP, which is modelled.)
PXP scale & colour-space convert
Blocked by the libg2d / pxp_dma_v3 driver stack itself (driver returns "unsupport 2d operation"; libg2d gates CSC on "unsupported alpha mode"), not a model gap. Copy/fill/blit/blend/rotate all work byte-exact.
Secure boot · ELE crypto services
Depend on per-die secrets (HUK, fused keys) that physically can't be modelled. Fuse reads work (plain data); the crypto engine is out of scope by design — and unused in emulation.
Bring-up-only blocks: FlexIO non-I²C modes
Modelled to driver registration, not a full data path (QEMU convention). FlexIO's SPI/UART/PWM shifter modes have no BSP user to exercise (its I²C-master mode is functional); the dw-mipi-csi2 host is a register stub, but it's enough for the subdev to bind and real capture to flow.
Pin-mux / reset / sysconfig: IOMUXC · SRC · BLK-CTRL
Logging stubs — pad muxing and reset assertion have no behaviour to emulate (QEMU has no pin fabric), so the model just answers the register accesses. Stubbed identically on the i.MX91 (shared lineage), so the gap reads the same on both.
The pattern:  if it's a silicon secret or closed driver behaviour, we model the interface and stop at the engine. If it's a QEMU limitation, we work around it transparently and write down exactly why. And where the 95 must say "NPU brings up but can't compute," the 93 says the NPU computes.
